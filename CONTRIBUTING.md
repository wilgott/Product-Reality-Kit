# Contributing

Thanks for wanting to improve Product Reality Kit.

This project is meant to be practical, direct, and useful for product people working in real B2B SaaS environments.

Please keep that style.

---

## What good contributions look like

Good contributions usually do one of these things:

- Add a practical diagnostic
- Improve an existing diagnostic
- Add a realistic example
- Make a question clearer
- Add a common false diagnosis
- Add a better Product Decision Record template
- Improve the AI prompts
- Make the language simpler

---

## Writing style

Use simple English.

Short sentences are good.

Clear beats clever.

Practical beats academic.

Avoid:

- Consultant-speak
- Heavy theory
- Long framework explanations
- Vague words like "leverage", "synergy", "robust", "optimize" without saying what you mean
- Content that sounds useful but does not help someone make a better decision

Prefer:

- Plain language
- Real examples
- Clear questions
- Trade-offs
- Red flags
- What to do next

---

## Tone

The tone should be:

- Practical
- Direct
- Senior
- Easy to understand
- A little sharp when useful

The goal is not to sound academic.

The goal is to help product people think clearly when the situation is messy.

---

## Contribution format

For a new diagnostic, use this structure:

```markdown
# When [situation]

## When to use this

## The uncomfortable truth

## First questions

## Red flags

## Common false diagnoses

## What to check

## Decision options

## Product Decision Record output

## Optional AI prompt
```

---

## Examples matter

A blank template is useful.

A worked example is better.

If you add a diagnostic, try to include a simple example that shows how it should be used.

Do not include private company data, customer names, or confidential information.

Use fictional examples.

---

## Before opening a pull request

Check that your contribution is:

- Easy to understand
- Useful in the first 30 seconds
- Specific enough to act on
- Clear about trade-offs
- Written in plain English
- Free from private or confidential information

---

## Project principle

Customer problem first.

Business reality included.

No framework theater.
